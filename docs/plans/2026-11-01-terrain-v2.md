# CityGenerator v2 plan — terrain relief

Status: approved 2026-11-01; revised after first visual review, see the last
section.

## Goal

Put the fused city on a real digital elevation model (DEM) instead of a flat 1 m
slab, without giving up the v1 contract: one watertight, outward-oriented
`city.stl` that can be imported as a single CFD obstacle.

## Design decisions

### 1. Data source

AWS Terrain Tiles (Terrarium, `elevation-tiles-prod`), fetched over plain HTTPS
with no API key:

```text
https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png
```

8-bit RGB PNG, non-interlaced, `metres = R*256 + G + B/256 - 32768`, derived from
SRTM/GMTED at roughly 30 m ground resolution. Decoded with Pillow (the only new
dependency). Zoom is chosen from the requested resolution and clamped to
`10–14`; the tile set is planned up front and the zoom is reduced one level at a
time if the plan would exceed `dem_max_tiles`.

Alternatives considered: OpenTopography (API key, quotas), Copernicus GLO-30
(large downloads, auth), local GeoTIFF upload (good, but a separate feature and
UI). Terrarium wins on zero setup and small tiles; a `DEMSource` protocol keeps
the door open for a local-GeoTIFF source later.

### 2. Height field and sampling

`TerrainGrid` stores `heights (ny, nx)` on a local metric grid
(`x0, y0, dx, dy`), plus `datum_offset_m` and source metadata. Sampling is exact
with respect to the mesh: each cell is split into two triangles
(`v00, v10, v11` / `v00, v11, v01`), so the STL surface and the placement
queries never disagree.

Buildings are placed with `min_over(footprint)`: the minimum over covering grid
nodes plus exact vertex and centroid samples. This is a conservative low bound:
a building may be buried a little on the uphill side, but it never floats.

### 3. Vertical datum

`z = 0` becomes the lowest terrain cell in the selection, so the CFD floor stays
at `0` and the model is not shifted by hundreds of metres. The removed offset is
recorded as `terrain.datum_offset_m` so absolute elevations can be restored.

### 4. Terrain solid

`build_terrain_solid` builds a closed block: top surface (two triangles per
cell), vertical skirt around the border, and a flat bottom at
`-ground_slab_thickness_m`. All faces are consistently wound; no boolean step is
needed to close it.

### 5. Fusion and correctness

The terrain block replaces the flat slab in the existing Manifold union, so
building bottoms embedded 0.5 m below `min_over` are cut by the hill and the
result stays one solid. The v1 round-trip validation (watertight, winding,
finite, volume, zero non-manifold edges) is unchanged and still applies.

### 6. Failure policy

A DEM failure must fail the job (`TERRAIN_FETCH_FAILED` /
`TERRAIN_DATA_MISSING`) rather than silently produce a flat site — a flat model
that looks plausible is worse than an error. The UI hints that terrain can be
switched off to retry. Nodata cells inside an otherwise valid grid are filled
from neighbours with a warning.

### 7. Two-phase building work

Terrain must cover the building footprints, so the pipeline needs the footprint
extent before sampling. `buildings.py` is split into `prepare_buildings`
(project, clean, resolve height, collect bounds) and `extrude_prepared` (place on
terrain, extrude, validate). `build_meshes` stays as the flat-ground wrapper.

## Pipeline stages

`validating → fetching → parsing → projecting → building (prepare) → terrain →
building (extrude) → ground → fusing → exporting → completed`

## API and schema

- `options.terrain = {"enabled": true, "resolution_m": 10.0}` (2–50 m).
- `GET /api/config` exposes `defaults.terrain` and `terrain_attribution`.
- Metadata `schema_version` becomes `2.0`; new `terrain` block, `ground.mode` /
  `ground.surface`, `city.terrain_triangle_count`, `local_frame.z_reference`.
- `buildings.geojson` gains `ground_m`, `roof_m`, `footprint_relief_m`.

## New settings

`CITYGEN_TERRAIN_ENABLED_DEFAULT`, `CITYGEN_TERRAIN_RESOLUTION_M`,
`CITYGEN_MAX_TERRAIN_CELLS`, `CITYGEN_DEM_URL_TEMPLATE`, `CITYGEN_DEM_ZOOM_MIN`,
`CITYGEN_DEM_ZOOM_MAX`, `CITYGEN_DEM_MAX_TILES`, `CITYGEN_DEM_TIMEOUT_S`,
`CITYGEN_DEM_MAX_RETRIES`, `CITYGEN_DEM_USER_AGENT`.

## New warnings and errors

Warnings: `TERRAIN_RESOLUTION_REDUCED`, `TERRAIN_RESOLUTION_LIMITED`,
`TERRAIN_ZOOM_REDUCED`, `TERRAIN_NODATA_FILLED`, `TERRAIN_FLAT_RELIEF`,
`STEEP_FOOTPRINT`.
Errors: `TERRAIN_FETCH_FAILED`, `TERRAIN_DATA_MISSING`.

## Tasks

1. `terrain.py`: grid, exact sampling, conservative footprint minima, closed
   solid, warnings.
2. `dem.py`: zoom choice, tile plan, cache, download/retry, decode, mosaic,
   nodata, cancellation, purge.
3. `buildings.py` refactor with terrain placement and `STEEP_FOOTPRINT`.
4. Pipeline, output metadata/GeoJSON/README, `FusedCity.base_mesh`, DEM cache
   cleanup.
5. Schemas, config endpoint, frontend toggle/resolution/stats/attribution/error
   hint.
6. Tests: terrain unit, DEM unit, pipeline flat + terrain, API config/422, live
   DEM smoke test.
7. Docs, CHANGELOG, version bumps, end-to-end run with screenshots.

## Acceptance

- Terrain on: `city.stl` is watertight with zero non-manifold edges for a real
  ~1 km² area, and buildings sit on the hill surface (no floating, visible slope
  cut in the viewer).
- Terrain off: the v1 flat geometry contract (one closed city on a 1 m slab),
  still emitted with metadata schema 2.0 and `terrain.enabled: false`.
- Offline test suite passes; `ruff` clean.
- A DEM outage produces `TERRAIN_FETCH_FAILED`, not a flat model.
- Cold generation with terrain stays within a few seconds of v1 for 1 km².

## Non-goals for v2

Roads, water, vegetation, cliff/building detail in the DEM, stream carving,
pitched roofs, volumetric meshing, and a local DEM upload UI.

## Revision after visual review: the relief looked fake

Reported bbox `28.19488, 112.96376 → 28.20445, 112.97091` (downtown Changsha,
~0.7 km × 1.07 km) showed 47 m of relief and, in one spot, a smooth 81 m dome.

Diagnosis (all numbers from `data/` probe scripts):

- Georeferencing is correct: at four points our values match `srtm30m` within
  0.6 m, and the raw z=14 tile pixel at the peak decodes to the same 80.2 m we
  sample. The tile is not misaligned.
- The dome is one bad 30 m SRTM cell. At z=11 it is invisible (64 m), at z=12 it
  is a single 78 m pixel, and the higher zooms upsample it into a ~100 m-wide
  dome (80–82 m). ASTER at the same point says 55 m and SRTM90m says 63 m; the
  point is not inside any mapped building (nearest footprint 24 m, all 25 m
  tall), so it is a radar/urban spike, not a real object.
- The rest of the field is also a surface model: 82 % local slopes at 10 m are
  an artefact of sampling a ~30 m DSM at 8 m, not terrain.

Fix:

- Default `terrain.resolution_m` is 30 m (allowed 5–50 m), the native spacing of
  the data; terrain triangles drop roughly 8×.
- `smooth_heights` applies an exact 2-D running median with a width fixed in
  ground metres (`150 m`), sampled with a margin and cropped so the border is
  not flattened by edge padding. Median keeps linear slopes and real landforms.
- `metadata.json` records `terrain.smoothing_m` and `terrain.filter`; the UI
  default and docs follow.

Verified effect on the reported bbox at 30 m: relief 37.3 → 32.1 m, peak
81.5 → 67.1 m (SRTM90m: 63 m), p99 slope 27.2 % → 14.3 %, max 33.7 % → 20.3 %.
Mount Yuelu keeps 268 of its 276 m of relief, and a flat riverside block stays
at 7.1 m. Regression test: a synthetic source with one +40 m cell produces a
grid whose relief stays within 5 m of the spike-free ramp.
