~1.2–1.8 s. `extrude_prepared` is the next lever, and `fuse_city` +
`write_outputs` together export and reload the city three times although only
one validated STL is needed.

### Steps

1. Profile `extrude_prepared` step by step (`_contact_indices`, per-shell
   `terrain.min_over`/`relief_over`, `extrude_building`'s triangulation,
   `fix_winding`/`fix_normals`, `_mesh_is_valid`) with
   `scratch/perf_profile.py`; record the before table.
2. Optimise the dominant step without changing any mesh: the acceptance run must
   keep 87 388 triangles, volume within 1e-4 relative, watertight, 0
   non-manifold edges, 0 weld repairs, and the same patch counts.
3. Remove the duplicate STL round-trip: `fuse_city` already exports and reloads
   the city to prove closure; return those validated bytes and the reloaded mesh
   in `FusedCity`, and let `write_outputs` write/validate them instead of
   exporting and reloading again. Keep the fallback for a hand-built
   `FusedCity` (no bytes): export, load, validate, then write.
4. Re-run the cached 4×4 sample and the golden test; write the interleaved
   before/after timing table into the handoff and CHANGELOG.

## Task 4 — CI hardening (P2)

### Brief

CI is Ubuntu-only, has no `timeout-minutes`, and the golden test compares
geometry without recording which dependency versions produced it, so a
dependency bump fails an unchanged commit with no explanation.

### Steps

1. `.github/workflows/ci.yml`: add `timeout-minutes` to every job and add a
   Windows job (`windows-latest`, Python 3.11) that installs, lints, and tests
   the same way; keep the pip cache (`cache: pip`).
2. Record the producer versions in `tests/golden/city_300m.json`: a `producer`
   block with `python`, `trimesh`, `manifold3d`, `pyproj`, `shapely`, and
   `numpy`, written by `UPDATE_GOLDEN=1`.
3. `tests/test_golden.py`: on a metric mismatch, include the recorded and the
   installed producer versions in the assertion message (the diff that explains
   an unchanged-commit failure); assert the golden file carries a producer
   block. Versions are a diagnostic, not an assertion: a bump alone must not
   fail the test.
4. Document the Windows job, the timeouts, and the producer block in the handoff
   and CHANGELOG.

### Acceptance

- Both jobs have `timeout-minutes`; the Windows job runs ruff and the full
  offline suite.
- Golden test failure output names both version sets; a version-only change
  leaves the test green (test the message helper directly).
- YAML parses (a small Python check in the task is enough); suite green; ruff
  clean.

## Task 5 — product polish / data hygiene (P3)

### Brief

Four independent polish items from the handoff. The UI shows a planar
`width × height` area (4 km = 16.000 km²) while the backend and the
`max_area_km2` check use the WGS84 ellipsoid (16.005 km²); `metadata →
buildings.height_sampling` changes shape depending on whether sampling ran; two
data questions (huge low-rise footprints, an optional OBJ with patch groups)
need a decision.

### Steps

1. **UI area.** Add a WGS84 graticule-cell area function to
   `app/static/js/map.js` and use it in `selectionFromBounds`
   (`areaKm2`); keep the haversine width/height readout. The closed form is
   `A = Δλ · a²(1 − e²) · [F(sin φ₂) − F(sin φ₁)]` with
   `F(u) = u / (2(1 − e²u²)) + artanh(e·u) / (2e)`. Verify it against
   `pyproj.Geod.polygon_area_perimeter` (the backend formula) for several boxes
   with a node-based test that skips when `node` is unavailable.
2. **Stable `height_sampling` shape.** Emit the same keys whether sampling ran,
   was disabled by settings, or had too few observations: `enabled`, `reason`,
   `known`, `jitter`, `seed`, `weighting`, `type_factors`,
   `area_bandwidth_log`, `area_ratio`, `area_weighted`, `conservative`,
   `slenderness_k`, `pool_above_100m`, `pool_above_250m`, `sampled`,
   `sampled_buildings`, `rules`, `type_capped`, `band_fallback_draws`,
   `sampled_above_100m`, `sampled_above_250m`, `above_100m_by_group`. Neutral
   values when sampling did not run (`reason` names why, zero counters, empty
   maps, the configured parameters). Update `height_report`'s "not recorded"
   path to key off `reason` instead of missing keys, and the tests that assert
   the shape.
3. **Huge low-rise footprints.** Rule: keep them. They are real OSM shapes, the
   task says removing them is a product decision, and `min_building_area_m2`
   is the documented user control (raising it drops small buildings, not large
   ones — so a new filter would be the only way to drop them). Record the
   decision and the rationale in `docs/osm-to-stl.md` (known limitations) and
   CHANGELOG.
4. **Optional OBJ with patch groups.** Rule: skip. It is marked optional, it
   would add a multi-megabyte file to every job and its download ZIP, and
   `patches.json` already gives Blender/Salome the same information. Record the
   decision and the escape hatch (a future `--obj` opt-in) in the CHANGELOG and
   the handoff.

### Acceptance

- The UI selection area for the 4×4 km box reads 16.005 km² (backend
  `area_km2` 16.005367), including the over-limit comparison; the JS formula
  matches `bbox_area_km2` within 1e-6 km² on the test boxes.
- `height_sampling` has the same key set in all three modes, asserted by tests;
  `height_report` still prints the pre-v3 "not recorded" notice for old jobs.
- Docs/CHANGELOG record the footprint and OBJ rulings.
- Suite green; ruff clean; frontend syntax checked with `node --check`.
