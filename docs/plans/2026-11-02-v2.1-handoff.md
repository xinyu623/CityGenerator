## What landed in ea4be95 (area-weighted sampling)

- **Area-weighted height sampling**: each known OSM height is paired with its
  footprint area; a draw for a target footprint prefers observations within
  0.25–4× its area and falls back to the whole pool. The target building uses
  the cleaned local polygon area; known areas come from the raw WGS84 footprint.
  `metadata.json → buildings.height_sampling` gains `area_weighted` and
  `area_ratio`. 4×4 km sample: log-log Pearson 0.36, median 3.1 m under
  2 000 m² vs 33.5 m above; 1 187 sampled from 512 known.

## What landed in 40f2c8a (P1-2)

- **`patches.json`**: every triangle of `city.stl` is classified as `ground`
  (upward and within `CITYGEN_PATCH_GROUND_TOLERANCE_M` = 0.05 m of the terrain
  surface), `wall` (building walls, roofs, the vertical terrain skirt), or
  `bottom` (the base underside, recognised as every vertex on the lowest plane —
  a normal-sign rule misclassified 241 noise-tilted wall triangles). Ranges are
  contiguous and in STL order, and the classifier runs on the reloaded
  `city.stl`, so the order is the file's own. Metadata gains a `patches` block;
  the file is in `metadata.json → files`, `result.zip`, and `README.txt`.
  4×4 km: 53 041 / 28 275 / 548 triangles (993 ranges); 0.74 km²: 10 303 /
  22 317 / 146 (471 ranges). Bottom area equals the base plan area.

## What landed in b026665 (P3-4)

- **Stage timings**: `stats["timings_s"]` and `metadata.json → timings_s`
  record `fetch`, `parse`, `prepare`, `terrain`, `build`, `ground`, `fuse`,
  `export`, and `total` (snapshot before the metadata write; the zip follows).
- **Fusion ~2× faster**: profiling showed the union is only ~0.3 s of the old
  4.4 s `fuse`; `trimesh` already does a balanced pairwise cascade,
  `Manifold.batch_boolean` saves ~0.1 s, and threaded grouping is slower (the
  bindings hold the GIL). The lever was the post-union work:
  `separate_collapsed_vertices` now uses one packed integer key per cell and 14
  neighbour directions instead of 27 coordinate tuples,
  `non_manifold_edge_count` packs each edge into one integer key instead of
  sorting a structured array, and the fused mesh is validated once. Interleaved
  cached 4×4 km runs: fuse 4.41 → 2.18 s, export 2.70 → 1.76 s, total 17.5 →
  13.9 s, with identical triangles, volume, zero welds, watertight, zero
  non-manifold edges.
- **Measurement caveat**: sustained CPU load throttles this machine ~4×, so
  compare before/after runs interleaved; an idle-machine run measured 8.2 s
  total. See `docs/architecture.md → Performance notes`.

## What landed in 680d9fe (P2-1)

- **P2-1 adaptive Overpass split**: after a chunk exhausts its endpoint retries
  it is retried as four sub-cells (`chunk_bboxes(cell, area / 4)`), at most two
  levels deep and never below 0.25 km² (`CITYGEN_OVERPASS_SPLIT_MAX_DEPTH`,
  `CITYGEN_OVERPASS_SPLIT_MIN_AREA_KM2`). Sub-cells are cached under their own
  bbox and the merged payload under the parent; a cell that cannot be
  subdivided still fails the job. `metadata.json → source.overpass_splits`
  records each split and `source.overpass_cell_times` the elapsed time of every
  cell the run touched. Tests cover a mocked 504 on one chunk, two-level
  recursion, the depth cap and the minimum area. The 4×4 km sample reruns from
  cache in 19.3 s with the reference numbers below.
- **CLI on GBK consoles** (`a8498dc`): the success summary used `km²`, which a
  cp936 console cannot encode, so the CLI crashed after finishing the job. It
  prints `km2` now and exits 0.

## Environment notes

- The UI server runs at <http://127.0.0.1:8000> **without `--reload`**:
  a reload during a job cancels the job and leaves the port unresponsive (the
  job thread keeps the process alive while the HTTP loop is gone). Restart by
  killing the `uvicorn.exe` tree and starting it again:

  ```powershell
  Get-CimInstance Win32_Process -Filter "Name='uvicorn.exe'" |
    ForEach-Object { taskkill /PID $_.ProcessId /T /F }
  Start-Process .\.venv\Scripts\uvicorn.exe `
    -ArgumentList "app.main:app","--host","127.0.0.1","--port","8000" `
    -WorkingDirectory (Get-Location) `
    -RedirectStandardOutput data\uvicorn.log -RedirectStandardError data\uvicorn.err.log `
    -WindowStyle Hidden
  ```

- `data/cache/osm` already holds the 4×4 km Chongqing chunk set and the 1 km²
  box, so those reruns take ~30 s instead of ~2–3 min.
- Public Overpass endpoints are intermittently at capacity (502/504). The client
  already rotates three endpoints with backoff.
- `scratch/` is gitignored: figures, v2.1 comparison outputs, and one-off probe
  scripts live there.

## Known issues / gotchas

- **STL float32**: the nudge only handles pairs closer than 0.5 mm. If a new
  non-manifold edge appears after geometry changes, check
  `separate_collapsed_vertices` first before adding weld boxes.
- **`--reload` + long jobs**: see the environment note; never run the UI server
  with reload while a job may be in flight.
- **UI area formula**: the front end uses planar `width × height` while the
  backend uses the ellipsoid (4×4 km = 16.000 vs 16.005 km²). The 17 km² cap
  hides it; worth unifying when touching the frontend.
- **Height sampling is area-weighted** (0.25–4× footprint area bands; see
  `metadata.buildings.height_sampling.area_ratio`).
- **Patch ground tolerance**: `patches.json` uses a 0.05 m distance test to the
  terrain surface, so a near-surface roof triangle on steep terrain can be
  labelled `ground`. Steep slopes are common in the 4×4 km sample; check
  `patches.counts` if a region looks off.
- **Manifold union and the GIL**: answered — the `manifold3d` bindings hold the
  GIL; threaded grouping of the union was slower (8 groups 0.77 s vs 0.24 s
  sequential), so there is no parallel-union path. `Manifold.batch_boolean`
  itself is only ~0.07 s faster than trimesh's cascade; the cost is post-union
  validation, now ~2× faster.
- Reference numbers for the 4×4 km Chongqing box
  (`29.553,106.546686 → 29.589069,106.588`), current after the height-sampling
  change: 1 696 buildings, 84 654 triangles, 39 460 terrain triangles, relief
  187.931 m, 0 welds, watertight, 0 non-manifold edges, volume
  1.35378e9 m³, 1 187 sampled heights from 512 known, patches 53 673 ground /
  30 433 wall / 548 bottom (910 ranges). The counts quoted in the landed
  sections above (`81 864` triangles, `53 041 / 28 275 / 548`) were measured
  before area-weighted sampling changed the sampled heights.
